# 語・句の集合における要素間アテンションの第二段階

2026年11月11日に、固定した重み、実行コード、日英の入力例を用意し、語彙のみをロードしてトークン化を検証した。埋め込み推論と層境界の測定は未開始。第一段階で観察した語義の変化と、語の組み合わせを見分ける能力を、年代と学習目的の異なる軽量モデルで調べる。 [第一段階の記録](../2026-11-11-set-context-phase-1/README.md) · [第二段階の事前検証](preflight.json)

## モデルと計算条件

第一段階の4モデルに4モデルを追加した。重みは1本650 MB未満で、CPU 4スレッド、最大128トークン、1プロセスにつき1モデルで順次実行する。埋め込みの精度と時間は本測定で記録する。

| ID | モデル | GGUF | 重み（MB） | 層数 | 選定理由 |
|---|---|---|---:|---:|---|
| `mbert` | BERT base multilingual cased | Q8_0 | 192.3 | 12 | 2018年の事前学習済みエンコーダー。文埋め込みへの特化を比較する対照。 [Google BERT](https://github.com/google-research/bert) |
| `labse` | LaBSE | Q8_0 | 514.9 | 12 | 2020年のプレプリントで報告された翻訳対を使う文埋め込み。 [プレプリント](https://arxiv.org/abs/2007.01852) · [ACL 2022](https://aclanthology.org/2022.acl-long.62/) |
| `minilm` | paraphrase-multilingual-MiniLM-L12-v2 | F16 | 242.4 | 12 | 第一段階と同じ多言語の言い換えモデル |
| `e5` | multilingual-e5-small | F16 | 242.4 | 12 | 第一段階と同じ多言語の検索モデル |
| `e5-base` | multilingual-e5-base | F16 | 562.8 | 12 | E5-smallとの同系列比較。 [技術報告](https://arxiv.org/abs/2402.05672) |
| `bge-m3` | BGE-M3 | Q8_0 | 634.6 | 24 | 多言語の検索向けエンコーダーを別系列から追加。 [モデルカード](https://huggingface.co/BAAI/bge-m3) |
| `qwen3` | Qwen3-Embedding-0.6B | Q8_0 | 639.2 | 28 | 第一段階と同じ因果マスク付きのモデル。 [技術報告](https://arxiv.org/abs/2506.05176) |
| `gemma2` | EmbeddingGemma 2 | Q8_0 | 309.9 | 24 | 第一段階と同じモデルのテキスト入力 |

ファイルの取得元とハッシュは [アセットロック](../../assets.lock.json) に記録した。多言語BERTは [Googleの固定リビジョン](https://huggingface.co/google-bert/bert-base-multilingual-cased/tree/3f076fdb1ab68d5b2880cb87a0886f315b8146f8) から変換し、再変換で同じSHA-256を確認した。固定した変換器はWordPieceにもBPE用の事前トークン化設定の識別を要求する。変換スクリプトではこのフィールドに既定値を入れ、元のトークンIDと特殊トークンを維持した。実験で使う各文字列は元の `tokenizer.json` と特殊トークン込みで照合する。 [変換コード](../../experiments/convert_phase2_mbert.py) · [変換条件とハッシュ](../../fixtures/set-context-phase2-derived.json)

全モデルで標準のプーリングを無効にし、最終層のトークン表現を同じ手順で読む。LaBSEのDense＋Tanh、BERTのMLMヘッド、検索向けモデルのタスク接頭辞は使わない。GGUFの精度、トークナイザー、アーキテクチャ、学習法はモデルごとに異なる。この構成で複数年代に共通する傾向が出ても、年代や学習法の効果を個別に推定したり、全埋め込みモデルへの普遍性を示したりすることはできない。

## 入力と評価

[固定入力](../../fixtures/set-context-ja-en-v2.json) に語義24例（日本語12、英語12）と組み替え32候補（日本語16、英語16）を収録した。各言語で半数を境界選定用、残りを評価用に割り当てた。語義の対象語と組み替えの例は分割間で重複しない。同じ関係の種類は両分割に含まれる。これらは手作業で作った短い入力であり、自然文での検索性能とは異なる。

事前検証で組み替え候補のうち28例が全8モデルで一致した。境界選定用は日本語8例と英語5例、評価用は日本語8例と英語7例。全入力の最大は特殊トークン込みで27トークンで、多言語BERTは異なる381文字列で元のトークンIDと一致した。事前検証は41.0秒で、うち重み検証24.9秒、コンパイル10.8秒、トークン化5.0秒だった。ダウンロードとBERTの変換にかかった時間はこの計測の範囲外。 [対象例のIDと各工程の時間](preflight.json)

- **語義。** 多義語1語と文脈を示す2語を一緒に入力する。各語義の参照は「定義文＋区切り」のトークン列と、対象語を単独でトークン化したときの本体トークンを同じシーケンスに連結する。対象語の本体トークンだけをプールして参照を作る。因果マスク付きのモデルでも、後ろに置いた対象語は定義文を参照できる。両文脈で正しい参照へのコサイン類似度が他方を上回るかを測る。対象語と定義文を別要素にして前半を遮断した参照（`k=floor(L/2)`）、文脈間のコサイン距離、両文脈の総トークン数が等しい部分集合も記録する。参照の作り方が第一段階と異なるため、正解率の差を条件変更の効果として解釈できない。
- **組み替え。** 元の集合と属性や位置を組み替えた集合で、特殊トークンを含む `(要素内位置, トークンID)` の多重集合が全モデルで一致する例を使う。元の集合と意味を保った言い換えの類似度を、双方から組み替えへの類似度と比較する。二方向とも上回れば正解とし、弱い方の差を記録する。トークン多重集合を一致させる制約は元の集合と組み替えに適用する。言い換えの語彙やトークン数は異なるため、語彙一致が順位に及ぼす影響は残る。
- **順序と層境界。** 各要素の位置は特殊トークン込みで0に戻し、シーケンスIDは全要素で0とする。要素を文字列順に正規化し、同じ位置のトークンを並べる。先頭の `k` 層の全ヘッドで要素間の参照を遮断し、残りの層ではモデル本来のマスクを使う。対象語や各要素のベクトルは本体トークン平均をL2正規化する。集合ベクトルは各要素のベクトルを等重みで平均し、再度L2正規化する。各境界で言語・課題ごとの先頭例について全順列の出力を比較する。文字列順への整列を省き、元の要素順を反転した場合の距離も全例で記録する。選んだトークン対でマスクの可否と重みを検査する。

境界選定用の例では全モデルで `k=0..L` を1層ずつ測る。語義と組み替えで別々に、両方向のコサイン差が `1e-6` を超えた例数を最大にする境界を選ぶ。同数なら、各例の小さい方の差の中央値が大きい境界を採り、それも同じなら小さい `k` を採る。評価用ではこの2境界と両端 `0, L` を測る。評価用を見て境界を選び直さない。層数が異なるモデル間では絶対値 `k` と深さの割合 `k/L` を併記する。

## 再現手順と記録

リポジトリのルートで実行する。CPUワーカーとヘッダーの準備には [ビルド手順](../../service/README.md#準備) を使う。

```bash
uv sync --locked --python /usr/bin/python3
python3 experiments/fetch.py minilm e5 qwen3 gemma2 labse e5-base bge-m3 ref-mbert
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 uv run --locked python experiments/convert_phase2_mbert.py
uv run --locked python experiments/set_context_phase2.py prepare
```

`prepare` はワーカー・重みのSHA-256を検証し、コンパイル後に `--tokenize-only` で最大トークン数、語義参照の対象語トークン、組み替えの位置とトークンの一致を検査する。出力した `runs/` 配下のディレクトリには、`plan.json`、全入力のトークンIDと長さ、コンパイラ、ワーカーのマニフェスト、処理時間、ログがある。

本測定を開始するときは、`PREPARED` を上記の `prepare` が表示した出力ディレクトリに設定する。下記はMiniLMの例。

```bash
uv run --locked python experiments/set_context_phase2.py run \
  --prepared "$PREPARED" --model minilm --split development --out runs/phase2-minilm-dev
uv run --locked python experiments/set_context_phase2.py run \
  --prepared "$PREPARED" --model minilm --split heldout --development runs/phase2-minilm-dev
```

実行時は固定した入力と実行ファイルを再検証する。各モデル・分割の出力ディレクトリに以下を保存する。

- `fixture.json` と `metadata.json` に使用した例、境界と選定元、準備計画のSHA-256を保存する。
- `raw.jsonl` に境界・例ごとの類似度、差、マスク検査、順序を変えたときの差を保存する。全条件の確認後に `summary.json` へ日英別と全体の集計を書く。
- `stages.jsonl` に壁時計の経過時間を秒で記録する。準備ではコンパイル、重みの検証、モデル別のトークン化、BERTトークナイザーの照合を記録する。本測定では重みのロード、コンテキストの初期化、参照計算、各境界の語義・組み替えの計算、集計を記録する。全体時間は各段階と重複する。失敗時に得られた出力とワーカーログも残す。
